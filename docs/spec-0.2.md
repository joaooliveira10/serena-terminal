# Serena Terminal 0.2 — specification

This is the working contract for version 0.2, written on 2026-10-14 after a design round of that day (five research lenses, three designs, two judges and a synthesis) and the decisions the owner took on its proposal the same day. It continues docs/spec-0.1.md: requirements are numbered R44 to R62, the test plan adds T15 to T20, and a requirement or a test with a lower number is the one of that document, as amended there and here.

It is kept as it was written, as the contract between the maintainer and the implementation, in the way docs/spec-0.1.md is: "the owner" is the maintainer, and "today" is 2026-10-14. It is not user documentation. When it was written, nothing of 0.2 was built, version 0.1 was about to be released from main, and T12, the acceptance of 0.1 with a real profile, had not been run. The notes of the design round (research reports, prototypes, bench outputs) are kept outside the repository, as those of 0.1 are; this text names them by the lens that made them: research-powershell, research-terminal, research-tools, research-posix and research-reader, and the three designs design-native, design-tools and design-memory. Unless a figure says otherwise, the round measured on the owner's machine (Windows 11, Windows PowerShell 5.1.26100.8115 with PSReadLine 2.0.0, Git Bash 5.3.15), in sandboxed homes, while the machine was busy. What another program does is given with the file and the tag it was read at and the day it was read; where it was not observed on a machine, it is worded as expected. Contrast figures are those of docs/contrast.md as `sereno check --markdown` generates it from the palette of Serena Theme v1.1.0 (commit a62ecad), read on 2026-10-14; "the regular variants" are the two dark and the two light ones. Where the proposal left room and the owner decided nothing, this text chooses, and says so in place: a choice is marked "this text's choice", and a way of reading a rule or a decision "this text's reading"; each of them waits for the owner to confirm it, as the amendments of docs/spec-0.1.md marked "for the owner to confirm" do.

## What 0.2 is, and what it is not

Version 0.2 is for people who program and install nothing more: it keeps the one promise of 0.1, that the command line follows the system's dark, light and high-contrast setting with measured legibility, and makes the prompt say more, all of it read inside the shell without starting a program. The result of the last command shows as text (`[1]`) and not by colour alone, with exact end-of-command marks; the git operation in progress shows as `feature|REBASE 2/5`, read from git's own files; the Python environment, an elevated, root or remote session and, in a Node project, the Node.js version read from the version resource of node.exe show on the first line; in a Serena tab of Windows Terminal a command of 10 seconds or more is expected to light the tab's bell without a sound (read in Windows Terminal's source, not seen), and the prompt names the tab after the folder and the branch and makes the path a link to its folder, which are expected to show and have not been seen. Git Bash inside Windows Terminal gets the same signs, with marks and a duration. The comfort keys gain Alt+w, which keeps a half-written line in the history, and Ctrl+f, which takes one word of a suggestion; outside Windows Terminal the `>` is expected to show again a line that does not parse, as the stock prompt does. In a Serena tab bat and the code inside delta's diffs are expected to use the sixteen slots, through the fragment (read in their sources, not measured); `sereno status` lists the user's tools and how each follows the palette, and says what a newer PSReadLine would bring, printing the command and never running it; help gains examples and a hint for a mistyped command. Version 0.2 is not the release for macOS and Linux (that is 0.3), and it adds no command (no `sereno keys`, `explain` or `history`), no flag, no program it starts, no network code and no artificial intelligence; it installs nothing, writes nothing that belongs to another program, does not configure fzf, delta's diff colours or Starship, and changes no hard limit of 0.1 except by the amendments the owner decided on 2026-10-14, listed in the next section, of which one adds a budget on the wait before the first prompt and none loosens a budget.

## What stays from 0.1

Every hard limit of docs/spec-0.1.md stays. Each is named below with the requirement that holds it, and each test that enforces one keeps enforcing it on what 0.2 adds, the file ROOT/shell/prompt.ps1 included where R44 takes it. Where the owner amended a requirement on 2026-10-14, the amendment is stated as an amendment of that requirement and marked "decided by the owner on 2026-10-14"; no hard limit is changed in any other way.

- **No network (R1, R2).** `go list -deps ./cmd/sereno` lists neither `net` nor `net/http`; sereno opens no connection and has no telemetry, account or update check. Nothing of 0.2 opens a connection: the look-ups of PATH (R56, R61, and R34 of 0.1 as R61 changes it) skip every entry that starts with \\, and a folder on a mapped network drive, which they cannot tell from a local one without a further call, is the one place where the file system may reach a server for them, as it does for any look-up of a program on PATH. The Quick Fix sequence OSC 9001 is rejected because Windows Terminal is expected to query the winget catalogue over the network when it receives one (see Deferred).
- **No dependency (R1).** go.mod declares `go 1.24` and has no require line; the six targets build with CGO_ENABLED=0.
- **One child process (R2, R20).** The probe of R20 stays the only process sereno starts. The new reports of `sereno status` (R51, R56) read folder names and files and start nothing.
- **The session files start no process and open no connection (R2, R23).** The rule is unchanged, and the shell tests still run start-up and prompt with PATH emptied. Amended, decided by the owner on 2026-10-14: the scan that enforces the rule, TestGeneratedShellFilesStartNoProcess, which fails on every `[System.Diagnostics.*]` type in init.ps1, gains exactly one exception, `[System.Diagnostics.FileVersionInfo]::GetVersionInfo`, which reads the version resource of a file and starts nothing (R61). No other member of System.Diagnostics, and nothing else the scan forbids, is allowed; the scan counts the uses of that member and expects those of R61; with layout (b) of R44 the same scan, with the same one exception, runs on prompt.ps1.
- **Where sereno writes (R2, R10, R16, R19, R20).** Only below ROOT, the one fragment path and the hook targets the user named; never sudo; never the settings.json or state.json of Windows Terminal, the registry, PATH, a stored execution policy, a login shell or the configuration of any emulator; and nothing in sereno claims that settings.json stays unchanged (R19). 0.2 reads more and writes nothing more: bat's config files, the stored environments of HKCU and HKLM (R55), the module folders of PSReadLine and the value of User Shell Folders that names Documents (R51), and the folders of PATH (R56) are only read. 0.2 adds no variable of its own that another program reads, apart from BAT_THEME in the fragment (below), and sereno never sets VIRTUAL_ENV_DISABLE_PROMPT (R48). The variables 0.1 already sets for other programs are unchanged: the environment map of R18, whose POWERSHELL_TELEMETRY_OPTOUT and POWERSHELL_UPDATECHECK PowerShell 7 reads, and LS_COLORS and LSCOLORS of R33, which ls reads.
- **ROOT (R10).** Amended, decided by the owner on 2026-10-14: where one init.ps1 cannot meet the budgets of 80 and 65 ms, layout (b) of R44 is taken, and ROOT/shell/prompt.ps1 is then an owned file like init.ps1, listed in R10, recorded in the manifest and removed by R39. ROOT gains nothing else. Every test still sets SERENO_SANDBOX.
- **The fragment (R16 to R18).** One file, in the one place R16 gives. Amended, decided by the owner on 2026-10-14 with the bell and the tools: the sentence of R18 "No other profile key is written" allows two keys more, `"bellStyle": "taskbar"` after showMarksOnScrollbar (R50), and `"BAT_THEME": "ansi"` in environment, right after SERENO_SESSION, only where R55 finds no theme of the user's. adjustIndistinguishableColors stays unset.
- **A plan before every write, the manifest, ownership and the lock (R12 to R15).** Unchanged. Every new file and key goes through the same plan, hashes and lock, and a second apply with nothing changed performs zero operations, also when R55 had to look at the stored environment and bat's config files.
- **Exact uninstall (R22, R39).** Unchanged, with prompt.ps1 among the owned files where R44 takes it.
- **The session files (R23).** The same bytes for every user of a version, ASCII only, nothing printed at start-up, safe to source twice, active only in ConsoleHost and in FullLanguage mode, read-only variables of the user's left alone. Unchanged. What 0.2 adds is written by the prompt, as 0.1 writes the palette and the marks there: the bell of R50, the title of R57 and the link of R62 are prompt output, and the key description of R52 shows only when the user asks for the list of keys.
- **Slots, not hex; reverse, do not paint (R6, R8).** internal/palette/serena.json stays the only source file with colour values, and the allowed SGR parameters stay those of R8, with the one exception for ESC[44;1m that R8 names. roles.json gains four roles, all inside that set: prompt.state 33, prompt.context 36, prompt.danger 7;31 and prompt.syntax 7;91; both new bands are reverse video.
- **The contrast gate (R9).** Unchanged floors, 4.5:1 for the regular variants and 7.0:1 for high contrast. The new roles stand at: slot 1 6.46:1 or more on the regular variants and 7.82:1 or more in high contrast (also the band of prompt.danger, whose text is the background colour on slot 1); slot 3 5.47:1 and 7.78:1; slot 6 6.18:1 and 7.58:1; slot 9 4.53:1 and 8.69:1 (also the band of prompt.syntax).
- **Languages (R5).** Amended, decided by the owner on 2026-10-14. What R5 leaves untranslated (command names, flags, plan verbs, JSON keys, warning ids, file contents) gains the short signs of the prompt: `admin`, `root`, `[N]`, `USER@HOST`, `(venv)`, `node:VERSION`, and git's state words `REBASE N/M`, `AM N/M`, `AM/REBASE N/M`, `MERGING`, `CHERRY-PICKING`, `REVERTING` and `BISECTING` (the first three without N/M where the step files hold no digits, R46). They are labels, like command names; git prints its own state words untranslated; and a translated sign would make the prompt bytes, and their golden files, depend on the machine. Every sentence stays in English and Brazilian Portuguese: the new warnings of `sereno status`, the help examples and the hint of R58, the closing line of apply and the key description of R52. R5 gains one sentence for that last case: the description of a key that init.ps1 binds exists in both catalogues, init.ps1 carries both texts (written in ASCII, as R23 asks, with the letters outside ASCII as `[char]` codes), and it picks one when it binds the key: SERENO_LANG, then $PSUICulture starting with `pt`, otherwise English.
- **Nothing installed (R40).** sereno installs no tool, font, shell, emulator or package manager, has no flag to do so and runs no installer. Amended, decided by the owner on 2026-10-14: besides the winget command for PowerShell 7 that pwsh.absent shows, `sereno status` may print one more command, the one of R51 that installs PSReadLine 2.4.5 for Windows PowerShell 5.1, pinned below 3.0. It is printed and never run. No command that installs any other tool is printed in 0.2.
- **Budgets (R42).** Amended, decided by the owner on 2026-10-14. The local budgets stay as R42 has them: on the owner's machine, under Windows PowerShell 5.1, dot-sourcing init.ps1 takes at most 80 ms in a Serena profile session and at most 65 ms in a hook session, and one prompt with the follow check active takes at most 2 ms; the gates of CI stay (150 ms, 210 ms for PowerShell 7 on Windows, and 10 ms; 60 ms and 10 ms for bash and zsh). R42 gains a third local budget, which R44 defines: in each kind of session, in the fixture R44 names, the dot-sourcing and the first prompt together take at most 40 ms more than with the init.ps1 of the 0.1.0 release, judged within one bench run against a copy of that file and confirmed on an idle machine (T19). When a feature breaks any of these budgets, the feature leaves 0.2 in the cut order of this document; a budget is never raised for a feature. The first prompt, which R42 printed and did not judge, is judged from now on as part of that sum.
- **What 0.1 left out on purpose (R43).** Amended, decided by the owner on 2026-10-14, in three points. The silent signal of a long command (R50) comes into 0.2; the owner had placed notifications later. bat, and the code inside delta's diffs, use the sixteen slots in a Serena tab through the variable BAT_THEME that the fragment's profile carries (R55), and `sereno status` reports the tools it finds (R56); nothing of bat's, delta's or any other tool's is written, no tool is installed, and fzf, delta's diff colours and Starship wait for a check on a screen. And the "no ... AI" of R43 becomes a standing rule: artificial intelligence comes, if ever, only as a separate add-on, never in the core. Every other clause of R43 stays in the words of docs/spec-0.1.md, which this list repeats in full: no emulator is built, bundled, installed or configured beyond the Windows Terminal fragment; no edit of settings.json (default profile, application theme, key bindings); no PowerShell 7 or PSReadLine installation or upgrade; no Starship, fzf, zoxide, eza, fd, ripgrep, tealdeer, Atuin, Carapace or mise, and of bat and delta only the variable above; no fonts or icons; no completions, aliases, abbreviations, history tools; no keys, explain or doctor; no OS detection on macOS or Linux; no in-band painting by default outside Windows Terminal; no tmux, screen, Zellij, WSL or SSH handling; no fish, Nushell or cmd; no iTerm2, Ptyxis, Rio, foot, Konsole or Terminal.app files; no winget, Scoop, Homebrew or distro packages; no code signing; no self-update or update check; no custom palettes; no switching while the shell is idle; Windows without Windows Terminal (conhost) gets the hook's colours only, and none of them in a plain console (R26); Windows Terminal older than 1.24 is not verified. Two features of 0.2 come near the words "WSL or SSH handling", and this text reads both as inside them (this text's reading). The sign of R49 reads SSH_CONNECTION, a variable the shell already holds, and shows it as a label, as `(NAME)` shows VIRTUAL_ENV; nothing else differs in a remote session: no palette is sent through or held back, no ssh program or configuration is read or written, and nothing is set on either end. And R54 does nothing for WSL: init.bash runs there as in 0.1, the marks are expected there and not tried, and the 9;9 mark is never written there.
- **bash and zsh stay small (R31 to R33).** No key binding, alias, completion or history setting, and exactly LS_COLORS and LSCOLORS exported. Unchanged; R54 keeps to it.
- **The comfort set (R27).** Only PSReadLine is used, no other module is imported, and nothing is bound outside the keys rule. R52 adds two keys to the set; nothing else changes.
- **The release (R41).** A draft release from a tag, actions pinned by commit, an attestation, unsigned programs, install scripts that place only the program. Unchanged, except that the archives carry README.pt-BR.md next to README.md (R60).
- **The name (docs/spec-0.1.md, Name).** Never ship a command called `serena`. Unchanged; 0.2 adds no command.
- **Never planned (docs/spec-0.1.md, Deferred).** Building or forking an emulator, telemetry, accounts, update checks at shell start, piping an installer from the main branch, changing the user's login or default shell. Unchanged.
- **Tier 1 (docs/spec-0.1.md, Key choices).** Windows 11, Windows Terminal and Windows PowerShell 5.1 with the PSReadLine 2.0.0 it ships. Every feature of R45 to R57 serves it; bash and zsh follow.

Other requirements of 0.1 change through the requirements below, and none of these changes touches a hard limit: R3 and the closing lines of apply by R58 (a hint after a usage error, examples in help, one line more after apply; no new command or flag, and the exit codes of R4 unchanged); R11 by R59; R26 by R45, R46, R48, R49, R50, R53, R57, R61 and R62; R27 by R52; R30 by R47; R31 by R45, R46, R48, R49, R50, R54, R57 and R62; R32 by R45, R46, R48 and R49; R34 by R61 (the look-up of PATH in init.ps1 skips the entries that start with \\); R37 by R47, R50, R51, R55 and R56; R41 by R60. docs/contrast.md, which `sereno check --markdown` generates, gains the four roles.

R45 The result of the last command, also without colour, and exact marks. R26, R31 and R32 change, here and in R46, R48, R49, R50, R53, R57, R61 and R62, which this requirement puts in one order (the order of the prompt string and of line 1 is this text's choice). The prompt string of the Serena prompt in PowerShell is, in order: the BEL of R50 where it applies; the marks of R26 where 0.1 writes them (WT_SESSION set, TERM_PROGRAM not vscode), with the D mark as below; the title of R57 where it applies; line 1; a line feed; the character > repeated $nestedPromptLevel + 1 times, in a colour given below; ESC[0m; one space; the end mark of R26. Line 1 is, in order, each part only where its requirement puts it: the band of R49 and a space; `(NAME)` of R48 and a space; `USER@HOST` of R49 and a space; PATH, in the link of R62 where that applies; a space and the branch (R26, R46); `|STATE` (R46); a space and `node:VERSION` (R61); a space and the duration of R26 (2 seconds or more, slot 8, one decimal); a space and `[CODE]`. After a command that failed, line 1 ends with `[CODE]` in slot 1 (role prompt.failed, 31) and the `>`s are in slot 1, as in 0.1; after one that succeeded there is no `[CODE]` and the `>`s are in slot 2. In a plain console (R26) line 1 is the same text without any sequence, so `[CODE]` shows there, where 0.1 shows no result at all. In PowerShell a command ran when $MyInvocation.HistoryId at the prompt differs from the one of the last prompt, and it failed when $? was false at the prompt's entry. CODE is 1 when $global:Error[0] is a record that was not $Error[0] at the last prompt (compared by reference), otherwise $LASTEXITCODE when it is a non-zero integer, otherwise 1; this fixes 0.1, whose D mark gave a stale $LASTEXITCODE after a failed cmdlet. The same CODE goes into ESC]133;D;CODE BEL. When no command ran since the last prompt (an empty Enter, Ctrl+C on the line), the prompt shows the result it showed last, and the end mark of the previous command is a bare ESC]133;D BEL, as in Microsoft's example (learn.microsoft.com/windows/terminal/tutorials/shell-integration, read 2026-10-14) and in VS Code's own script (shellIntegration.ps1 at tag 1.141.2, lines 106-163, read 2026-10-14); by Windows Terminal's source (adaptDispatch.cpp at v1.24.12741.0, read 2026-10-14) that mark on the scrollbar is then expected to keep the colour of a prompt, where 0.1 gave it the colour of success. The first prompt of a session shows no result: no `[CODE]`, the `>`s in slot 2 and no D mark, as in 0.1. Where the result is unknown (R48) there is no `[CODE]`, the `>`s are in the default colour (ESC[39m, role default) and the D mark is bare. $LASTEXITCODE and $Error stay as they were. In Windows PowerShell 5.1 a native command whose error stream is merged into its output (2>&1) is expected to make error records, so that it shows `[1]` and not its own code; the documents say so (not tried for this text). bash: the prompt function keeps $? in the variable __sereno_code, and PS1 refers to that variable and never has the value pasted into it; an empty line leaves $? as it was, so the result stays; a bare D needs the flag of R54. zsh: %(?..) and %? in PROMPT. The exact strings of PS1 and PROMPT are fixed by the golden files of T8. No setting: prompt=on covers it. Shells and systems: Windows PowerShell 5.1 and PowerShell 7 on every system; bash 3.2 and newer (the bare D only where R54 writes marks, bash 4.4 and newer); zsh, CI only. Marks only where 0.1 writes them. Default: on, with prompt=on. Tests: T7, T8.

R46 The git operation in progress, read from git's own files. Where R26, R31 and R32 read the branch, the prompt also looks, in the git folder they resolved (that of a worktree or of a submodule included, through the gitdir: line of a .git file), for git's state files, in the order of git's own prompt script (contrib/completion/git-prompt.sh at v2.56.0, lines 364-390 and 511-533, read 2026-10-14; that file is under the GPL, so its labels are used and none of its code is copied), and puts the label right after the branch, joined by `|`, in slot 3 (new role prompt.state, 33). The first case that applies gives the label, and there is one label at most: the folder rebase-merge (files msgnum, end, head-name) gives `REBASE N/M`; the folder rebase-apply (files next, last) gives `REBASE N/M` when it holds the file rebasing, `AM N/M` when it holds applying, and `AM/REBASE N/M` when it holds neither (git's script reads next and last for every case of rebase-apply and appends the step to whatever label it found, lines 518-519 and 587-588); then the file MERGE_HEAD gives `MERGING`; CHERRY_PICK_HEAD gives `CHERRY-PICKING`; REVERT_HEAD gives `REVERTING`; otherwise the first word of sequencer/todo, `p` or `pick` giving `CHERRY-PICKING` and `revert` giving `REVERTING`; then BISECT_LOG gives `BISECTING`. N and M are shown only when they are digits; a step file that holds anything else gives the label alone. During a rebase the name shown is head-name without refs/heads/, not a hash. A detached HEAD is shown as its first 7 characters in parentheses, `(0123456)`, so that it cannot be read as a branch of that name. A HEAD that reads `ref: refs/heads/.invalid` next to a folder named reftable gives no branch, instead of `.invalid` (the reftable format keeps that stub as HEAD; tried with Git 2.55.0.windows.5 on 2026-10-14). Control characters are removed from head-name and the label, as init.ps1 and init.bash of 0.1 remove them from the branch. The step files are read only during a rebase; a state file that cannot be read at that moment gives the prompt without the state, and no failure and no message. PowerShell: [System.IO.Directory]::Exists and [System.IO.File]::Exists; bash: builtins only, one glob of the git folder where the shell allows it and file tests where failglob is set; the label reaches PS1 through a variable and PROMPT through psvar, never as pasted text. No process, and no git. The labels are git's English words and are not translated (R5, amended). That git keeps these files as its prompt script reads them is expected from that script; the tests build the files themselves (T17). Shells and systems: PowerShell 5.1 and 7, bash, and zsh (CI only), on every system, wherever 0.1 reads the branch. Default: on, with prompt=on. Tests: T7, T8, T17.

## Biggest risks

- The wait before the first prompt. Both prototypes of the design round came to 34 to 72 ms more than 0.1 for the dot-sourcing and the first prompt together, on a busy machine (R44), against the 40 ms the owner allowed. Mitigation: code that the start does not need sits in script blocks; layout (b) where one file cannot meet 80 and 65 ms; the difference taken within one run, so that a busy machine moves both files alike; the idle bench of T19; the cost of each feature printed by T9 (5); and the cut order, which takes features and never raises a budget, and sends a miss at step 4 to the owner before more code is added.
- Layout (b) is a change of architecture: a second owned file, a session whose first prompt meets a prompt.ps1 of another version, an uninstall before a session's first prompt. Mitigation: the mark both files carry, the plain text prompt as the fallback, all of R23's scans on both files, and T6 and T7 for each case.
- Windows Terminal is read in its source and not seen for most of what 0.2 adds: the bell icon and the flash of the taskbar, the colour of a bare D mark, the title, Ctrl+click on a link, the profile it is expected to drop for a bellStyle it does not know, and cells after 133;B taken as command text. Mitigation: only values of the stored release-1.24 schema; no OSC 777; every such sentence worded as expected; T20 looks.
- Every BEL in a Serena tab becomes a bell mark, also those of vim and less. The owner accepted it on 2026-10-14; the documents name Windows Terminal's own bell setting of the profile as the switch.
- The venv rule depends on how CPython's Activate.ps1 wraps the prompt at v3.14.0, and was designed, not tried; virtualenv's script of the same name was not read. Mitigation: a prototype before it is built, and a fallback that leaves the result out, which is never a false result.

- 0.2 replaces things of the user's in a Serena tab: his bindings of Alt+w and Ctrl+f (under the keys rule), his PromptText, and titles that programs set. Mitigation: `--keys off`, suppressApplicationTitle, and the documents.
- The command of R51 has not been tried on a clean Windows PowerShell 5.1 machine, and whether PowerShellGet 1.0.0.1 honours -MaximumVersion is not verified; after it, PSReadLine's own messages are expected to be English. Mitigation: it is printed and never run, Microsoft's page on the prerequisites is named, and the warning says what changes.
- R61 rests on the ProductName test against shims and on a warm cost that was not measured. Mitigation: two conditions in the requirement, the case in bench.ps1, and R61 second in the cut order.
