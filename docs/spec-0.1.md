# Serena Terminal 0.1 — specification

This is the working contract for version 0.1, written on 2026-10-07 after a research and design round.
Requirements are numbered R1 to R43; the test plan is T1 to T14.

It is kept as it was written, as the contract between the maintainer and the implementation: "the owner" is the maintainer, and "today" is the day a sentence was written. It is not user documentation; that is the README and the other files in this folder.

## Decision

Build Serena Terminal 0.1 as `sereno`: one dependency-free Go command, not an emulator, whose single promise is that the command line follows the system's dark, light and high-contrast setting with measured legibility, on a stock Windows 11 machine with nothing else installed, and that one command removes everything it wrote. The differentiator, the palette routes (emulator-native, host, in-band OSC), the per-prompt OS check without a child process, the contrast gate and the rules 'slots, not hex' and 'reverse, do not paint' come from the most-distinct proposal. The safety envelope comes from smallest-useful: by default sereno only creates files it owns (one folder plus one Windows Terminal fragment), the payload is static and golden-tested, Windows PowerShell 5.1 is a first-class target, the session is started by an added profile using `-ExecutionPolicy RemoteSigned -File`, PSReadLine gets a small comfort set, and four generated emulator themes give macOS and Linux something real; its honesty about what Windows Terminal writes on its own is kept and corrected. The engine comes from best-experience and the distribution research: a Go binary from day one (so there is no rewrite later), a plan before every apply, a manifest with SHA-256 guards, an opt-in one-line hook with backups, English and pt-BR catalogues, no net/http, and tests that hash the whole home tree before install and after uninstall. Left out on purpose: installing or configuring any emulator (WezTerm included), Starship and the eight-tool core, fonts, PowerShell 7 installation, completion and history tools, keys/explain/doctor, package-manager channels, and OS detection on macOS/Linux. The design degrades safely: if the day-one spike shows the in-band route misbehaves on screen, 0.1 still ships as six schemes, a legible shell layer and exact uninstall, and following falls back to Windows Terminal's own scheme pair.

## Name

Display name 'Serena Terminal', repository `serena-terminal` (github.com/joaooliveira10/serena-terminal returned 404 today, so it is free), executable `sereno`, Go module github.com/joaooliveira10/serena-terminal with the main package in cmd/sereno. Never ship a command called `serena`: oraios/serena (30,084 stars, pushed 2026-10-06) declares `serena`, `serena-agent` and `serena-hooks` in its pyproject [project.scripts] (read today). Checked today for `sereno`: no command of that name on the owner's PATH; not on PyPI, crates.io, Homebrew (formula or cask), Scoop Main or Extras, or winget; npm has an unrelated 0.0.1 placeholder from 2022 (irrelevant, nothing is published to npm); GitHub has only small unrelated repositories (largest 13 stars; lytics/sereno is a Go library from 2017, not a command) and a user account `sereno` with no repositories. The first sentence of the README must say that Serena Terminal is not a terminal emulator and is unrelated to the Oraios tool. Not verified: trademark status of Serena or Sereno.

## Key choices

- Differentiator (one): the command line follows the system (dark, light, high contrast) and its legibility is measured. Evidence checked today: Windows Terminal's shipped theme is "dark" on release-1.24, release-1.25 and main, so a light/dark scheme pair never follows Windows unless the user changes a global setting; PSReadLine issue 464 (use a light theme on light backgrounds) is still open since 2016-11-09; tinty v0.34.1 still ships no Windows asset. Not chosen: 'exact uninstall' (hygiene, kept as a requirement) and 'cheat sheet equal to real bindings' (later feature).
- Product shape: a companion command plus generated configuration. Not an emulator, not a dotfiles repository, not a fork of WezTerm, not a shell plugin collection.
- Emulator default: none is installed or required. Tier 1 host is Windows Terminal through a per-user JSON fragment (owner has 1.24.12741.0; 1.25.2733.0 is the current stable, published 2026-10-02). VS Code's integrated terminal is a host route: Serena Theme already owns its palette, so sereno never repaints there. Not chosen: WezTerm as reference emulator (latest stable still 20240203, only nightlies since; revisit when its next stable ships), Ghostty and kitty (no Windows build).
- Theme-port tier: six schemes generated from one palette file. Tier 1 (seen by the maintainer): Windows Terminal. Tier 2 (generated, grammar-checked in CI, labelled 'not visually verified'): Ghostty, kitty, WezTerm, Alacritty through `sereno export`, written to a folder the user chooses, with the activation line printed and nothing installed into emulator folders. Later: iTerm2 and the upstream submission to iTerm2-Color-Schemes for the long tail.
- Shell strategy: configure the shell the user already runs, never replace it, never change a login or default shell. 0.1 covers Windows PowerShell 5.1 and PowerShell 7 with one feature-detected init.ps1 (tier 1), and bash 3.2+ and zsh with a deliberately small layer (prompt, slot colours, ls colours; tier 2, zsh is CI-only because neither this machine nor its WSL has zsh). PowerShell 7 is never installed by sereno. Not chosen: PowerShell 7 as the only shell on macOS/Linux, fish as base (no native Windows build), Nushell (0.x), ble.sh.
- Entry mechanism: on Windows the added 'Serena' profile carries the init, so the default install edits no file of the user's. Everywhere, `--hook` is the opt-in that appends exactly one guarded ASCII line to a profile or rc file (this is what brings Serena colours to VS Code's terminal and to existing profiles). Not chosen: ZDOTDIR or --rcfile wrappers (side effects on other dotfiles and history not verified), managed blocks, profile replacement.
- Theming rule: only the emulator knows hex values. Everything above it uses the 16 palette slots, and highlighted bands use reverse video, never a fixed foreground on a background slot. Role to slot: function/command 4, keyword 5, string 2, type 3, property/member 6, constant/number 11, parameter italic 7, comment 8, error 9. Measured today on the built themes: slots 1-15 on the background are at least 4.51:1 (regular variants) and 7.28:1 (high contrast); foreground-slot on background-slot pairs reach 4.5:1 in only 21, 21 and 22 of 120 cases on the dark variants and 0 of 120 on the light ones.
- Core tools: none installed and none required in 0.1. The prompt is built in and starts no process (prototypes measured 0.33-0.46 ms per prompt here, against 29-36 ms for one process spawn). Starship, fzf, zoxide, bat, eza, fd, ripgrep, tealdeer become optional adapters in 0.3, wired only when already present. Never in a default: Atuin, mise, Carapace on Windows PowerShell 5.1.
- Font: nothing is installed. The Serena profile names Cascadia Code, which ships inside the Windows Terminal package (CascadiaCode.ttf, CascadiaCodeItalic.ttf, CascadiaMono.ttf, CascadiaMonoItalic.ttf found in the 1.24.12741.0 install folder today) and is the face of the Serena Theme screenshots. The prompt is ASCII only, so no Nerd Font is needed. Fonts and icons are a later opt-in pack.
- Implementation language: Go, standard library only (go.mod without require lines). Go 1.27.1 is on the owner's machine and Go is one of his daily languages; the registry is read through package syscall. Not chosen: Node or PowerShell/sh installers (two codebases, no rollback logic), Rust (no toolchain here), any TUI or HTTP library.
- Installer design: the binary is the installer and installing the binary changes nothing. `apply` computes and prints a plan, then writes owned files, a fragment and (only on request) one hook line, each recorded in a manifest with SHA-256; `uninstall` deletes an owned file only if its hash still matches and removes exactly the bytes it inserted into a profile. No transactional `undo` command in 0.1: with this write set, `uninstall` (optionally `--hook LIST`) is the undo. Not chosen: winget configure / Brewfile, chezmoi or Stow, editing settings.json.
- Packaging for 0.1: GitHub Release archives for six targets with checksums.txt and a GitHub artifact attestation, tag-pinned install.ps1 / install.sh that verify SHA-256 and place only the binary, and `go install .../cmd/sereno@v0.1.0`. The release workflow uses plain `go build` and creates a draft release (the owner publishes). Unsigned. Later: Scoop bucket and Homebrew source formula (0.2), winget and a SignPath Foundation application (0.3). Not chosen now: GoReleaser, casks, self-update.
- Licence: MIT, the same as Serena Theme (LICENSE and package.json read locally today), so palette data moves between the two repositories without conditions.
- Languages of the interface: English and Brazilian Portuguese from the first release, chosen by --lang, SERENO_LANG, then the OS UI language (pt-BR on the owner's machine). Command names, flags, plan verbs, JSON keys and warning ids are not translated. README in English with README.pt-BR.md.
- Privacy: no network code (test: the binary's dependency list has no net or net/http), no telemetry, no account, no update check. In PowerShell 7 sessions started from the Serena profile, the profile's environment map sets POWERSHELL_TELEMETRY_OPTOUT=1 and POWERSHELL_UPDATECHECK=Off (the `environment` key exists in the release-1.24 schema).
- CI: GitHub-hosted windows-latest, macos-latest and ubuntu-latest as the brief requires. Read today: they map to Windows Server 2025 (image 20260925, PowerShell 7.6.6, Git Bash 5.3.15, Go 1.24.13, no winget or Windows Terminal listed), macOS 26 arm64 (image 20260907, Bash 3.2.57, PowerShell 7.6.5) and Ubuntu 24.04 (Bash 5.2.21, PowerShell 7.6.6); ubuntu-latest moves to 26.04 in November 2026 (runner-images issue 14748). Tests therefore depend on nothing image-specific except those shells.
- Effort and order (my estimate): about 3,000 lines of Go, 450 lines of shell templates, 1,500 lines of tests; two to three weeks elapsed with the assistant implementing and the owner giving about one hour (20-minute spike, 30-minute acceptance). Cut order if it slips: `export`, then zsh, then the install scripts. None of these touches the differentiator.
- Evidence for today's checks (scripts, fetched sources, outputs): (local research notes, not in the repository) Nothing was created or changed under this repository or the Serena Theme repository, nothing was installed, no setting was changed.

## Requirements

R1 Identity and build. Repository serena-terminal; Go module github.com/joaooliveira10/serena-terminal; one executable built from ./cmd/sereno, named sereno (sereno.exe on Windows). go.mod declares `go 1.24` and has no require lines. Builds with CGO_ENABLED=0 for windows, darwin and linux on amd64 and arm64. `go list -deps ./cmd/sereno` must list neither `net` nor `net/http`. The version comes from -ldflags "-X main.version=..." and defaults to `dev`; `sereno version` prints `sereno <version> (<os>/<arch>)`. In this text ESC is byte 0x1B, BEL is 0x07 and ST is ESC followed by a backslash.

R2 Hard limits, each enforced by a test. sereno never opens a network connection; never starts a child process except the single probe in R20; never writes outside ROOT (R10), the fragment path (R16) and a hook target the user named (R20); never calls sudo; never writes Windows Terminal settings.json or state.json, the registry, PATH, a stored execution policy, a login shell, or any emulator's configuration. The shell files it generates start no process and contain no network call.

R3 Commands, exactly: `sereno apply [--dry-run] [--hook LIST] [--shell auto|powershell|pwsh] [--no-profile] [--keys profile|always|off] [--prompt on|off]`; `sereno uninstall [--dry-run] [--hook LIST]`; `sereno theme [auto|dark|light|hc|hc-light] [--flavor soft|vivid] [--inband profile|always|off] [--show] [--paint VARIANT] [--reset]`; `sereno status [--json]`; `sereno check [--json|--markdown]`; `sereno export [--target all|ghostty|kitty|wezterm|alacritty] [--to DIR]`; `sereno version`; `sereno help [COMMAND]`. Global flags: `--lang en|pt-BR`, `--no-color`, `-h`/`--help`. LIST is comma-separated from powershell, pwsh, bash, zsh. VARIANT is one of dark, dark-vivid, light, light-vivid, hc, hc-light. An unknown command, flag or value prints usage on stderr and exits 2.

R4 Exit codes: 0 done (including nothing to do); 1 runtime failure (I/O or internal error) and, for `check`, any value under its floor; 2 usage error; 3 refused before writing anything (a foreign file is in the way, a profile is a symlink or unreadable, a blocking execution policy, a requested shell is absent, `theme` or `export` to ROOT before any apply); 4 finished but something was left in place (an owned file the user edited). Results go to stdout, errors and refusals to stderr.

R5 Languages. Every sentence shown to the user exists in English and Brazilian Portuguese in internal/i18n (two Go maps with identical key sets; a test fails on any missing key). Selection order: --lang, SERENO_LANG, the OS UI language (Windows: GetUserDefaultUILanguage with primary language 0x16 means pt-BR; elsewhere LC_ALL, LC_MESSAGES, LANG starting with `pt`), otherwise English. Not translated: command names, flags, the plan verbs of R14, JSON keys, warning ids, file contents. The pt-BR wording is the implementer's faithful translation; acceptance checks key parity, not wording. sereno's own output is coloured only with slot SGR codes, only when stdout is a terminal and neither --no-color nor NO_COLOR is set.

R6 Palette data. internal/palette/serena.json is the only source file containing hex values. It is produced by `go run ./internal/tools/importpalette --themes DIR --tag v1.1.0` from the six files DIR/serena-*-color-theme.json of Serena Theme at tag v1.1.0 (the tool drops lines beginning with `//` before parsing; the built themes start with such a line). Per variant it stores id, name, kind, background (terminal.background), foreground (terminal.foreground), cursor (terminalCursor.foreground), ansi[0..15] (terminal.ansiBlack, Red, Green, Yellow, Blue, Magenta, Cyan, White, then the eight terminal.ansiBright* in the same order), selectionBackground (terminal.selectionBackground if present, otherwise the first 7 characters of editor.selectionBackground) and selectionForeground (terminal.selectionForeground if present, otherwise foreground); plus source {repo, tag, commit}. Running the tool again on the same tag reproduces the file byte for byte. Anchor values read today (background/foreground): Serena Dark #16171d/#d4d4dc, Dark Vivid #13141b/#d4d4dc, Light and Light Vivid #ecedf3/#323445, High Contrast #0b0c12/#f2f2f8, High Contrast Light #ffffff/#0b0c12.

R7 Variants (id, scheme name, kind): dark 'Serena Dark' dark; dark-vivid 'Serena Dark Vivid' dark; light 'Serena Light' light; light-vivid 'Serena Light Vivid' light; hc 'Serena High Contrast' hc; hc-light 'Serena High Contrast Light' hc-light. The scheme names are used verbatim in every emulator file.

R8 Slots, not hex. internal/palette/roles.json maps roles to SGR parameters: function/command 34; keyword 35; string 32; type 33; property/member 36; constant/number 93; parameter 3;37; operator 37; variable and default 39; comment 90; error 91; emphasis 96; selection 7; prompt path 34; prompt branch 35; prompt ok 32; prompt failed 31; prompt meta 90. Everything sereno generates above the emulator (the three init files and sereno's own output) may use only SGR parameters 0, 1, 3, 4, 7, 22, 23, 24, 27, 30-37, 39, 90-97. A test scans the rendered init files and fails on 38, 48, 40-47, 49 or 100-107 inside any SGR sequence. One sequence is allowed in one place: ESC[44;1m, the stock value of PowerShell 7 that init.ps1 compares a style with in R25 and never writes; the scan allows it on the line that sets it and fails on it anywhere else.

R9 `sereno check` (contrast gate, WCAG relative luminance). For each variant, with floor 4.5 for kinds dark and light and 7.0 for hc and hc-light: (a) ansi[1..15] against background at or above the floor; (b) ansi[0] against background at or above the floor only where the background is light (light, light-vivid, hc-light); it is exempt on dark backgrounds, where it is a surface colour (1.21-1.52:1 today); (c) foreground against background at or above the floor; (d) cursor against background at least 3.0; (e) selectionForeground against selectionBackground at or above the floor, and the better of black or white against selectionBackground at or above the floor (Windows Terminal 1.24 draws selected text in black or white); (f) the roles.json rule of R8. Output: one line per variant with the minimum of (a), then failures; `--json` gives the same data; `--markdown` prints the table committed as docs/contrast.md. Exit 1 on any failure. Expected minimums for (a) with today's palette: dark 4.52, dark-vivid 4.52, light 4.51, light-vivid 4.51, hc 7.82, hc-light 7.28.

R10 Owned root. ROOT is %LOCALAPPDATA%\sereno on Windows and ${XDG_DATA_HOME:-$HOME/.local/share}/sereno on macOS and Linux; SERENO_HOME (absolute path) overrides both. Inside ROOT sereno owns shell/init.ps1, shell/init.bash, shell/init.zsh, mode, manifest.json, backups/ and, after `export` without --to, themes/. ROOT/bin belongs to the install script (R41) and is never touched by apply or uninstall. While a command writes, ROOT also holds an empty file `lock`, which that command locks through the operating system and deletes when it is done (R13); the manifest does not list it, and one that a killed command left behind is taken, and taken away, by the next command that writes; anything else under that name (a file with content, a folder) is not sereno's and is a refusal like any foreign file (R15). When SERENO_SANDBOX is set to a directory, any create, write, rename or delete outside it fails with exit 1 before it happens; every automated test sets it.

R11 Mode file. ROOT/mode is ASCII with LF and exactly five lines in this order: `mode=auto|dark|light|hc|hc-light`, `flavor=soft|vivid`, `inband=profile|always|off`, `keys=profile|always|off`, `prompt=on|off`. First-apply values: auto, soft, profile, profile, on. It is rewritten only by `apply` and `theme`. Shell hooks treat a missing or malformed file as those defaults. The bytes decide, in Go, in PowerShell and in bash and zsh alike: a file that starts with a byte order mark, or was saved as UTF-16, is malformed.

R12 Manifest. ROOT/manifest.json (UTF-8, LF, two-space indent, keys sorted, no timestamps, so a second identical apply leaves it byte-identical) holds: schema 1; version; options {shell, profile, hooks}; owned (absolute path to SHA-256 of what sereno last wrote, including mode and the fragment); dirs (directories sereno created, in creation order); hooks (one entry per hook: shell, path, fileCreated, dirsCreated, beforeSha256, backup, inserted as base64 of the exact bytes added).

R13 apply, two phases. Phase 1 computes every operation and every refusal without writing. If there is any refusal, all are printed, exit 3, nothing is written. `--dry-run` prints the plan and ends with `Nothing was changed.` / `Nada foi alterado.` Phase 2 performs, in order: directories, backups of files about to be edited, manifest (already listing the hashes about to be written), owned files, hook lines. Every file is written to a temporary name in the same directory and renamed. If phase 2 stops before its end (an operation fails, or the run is interrupted, which takes effect between two operations), the manifest is written once more so that it records only what was carried out: a file that was not replaced keeps its old hash and is not taken for one the user edited. Options not given on the command line keep the values recorded by the previous apply; first-run defaults are shell auto, profile on, keys profile, prompt on, no hooks. `--hook` adds to the recorded hooks; it never removes one. Two commands do not write one folder at the same time. Phase 2 of every command that writes (apply, theme, export without --to, uninstall) holds the lock of R10, and once it has it, it computes its plan again, because only then can no other sereno change what the plan was computed from. When another command holds the lock, or the manifest is no longer the one the plan was computed from, the command ends with exit code 1 before its first write and prints `another sereno is working on this folder; run the command again when it has finished` / `outro sereno está trabalhando nesta pasta; rode o comando de novo quando ele terminar`; when the plan differs for another reason, it ends the same way and names the path that changed. The directories that lead to ROOT are the one thing a command creates before it can take the lock; each of them is recorded by the command that created it, also when that command then has to make way.

R14 Plan output. One line per operation: two spaces, a verb padded to 8 columns, the absolute path, an optional note in parentheses. Verbs: mkdir, create, replace, keep (already as wanted), skip (left as is, with the reason in the note: owned but edited by the user, which ends the run with exit 4, or not written this time, as the fragment of R16, which does not), append (hook line; the next line shows `+ ` and the exact text; when the line replaces an older sereno line in place, a line with `- ` and the old text comes first), remove, rmdir. A header line `sereno <version>: plan` precedes the list and a one-line summary follows it. The same code path produces the dry-run output and the real run.

R15 Ownership rules in apply. A target path that exists and is not in the manifest is a refusal (exit 3). A path in the manifest whose current hash equals the recorded one is replaced when the new content differs, otherwise kept; one that would be replaced and that the user has marked read-only is skipped and reported like an edited one (exit 4). A path in the manifest whose hash differs from the recorded one was edited by the user: it is skipped and reported, and the run ends with exit 4. A path in the manifest that no longer exists is created again. Running the same apply twice performs zero operations the second time.

R16 Windows Terminal detection and fragment path (Windows only). Windows Terminal counts as present when any of these exists: %LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_8wekyb3d8bbwe\LocalState, %LOCALAPPDATA%\Packages\Microsoft.WindowsTerminalPreview_8wekyb3d8bbwe\LocalState, %LOCALAPPDATA%\Microsoft\Windows Terminal. When present, apply writes exactly one file, %LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\SerenaTerminal\sereno.json, creating missing parent directories (recorded in dirs). When absent, the fragment is skipped with a note and `status` reports warning wt.not-detected. The file is UTF-8 without BOM, LF, four-space indent, fixed key order, final newline, with top-level keys `profiles` then `schemes`.

R17 Fragment schemes. `schemes` has six objects in the order of R7, each with exactly these keys in this order: name, background, foreground, cursorColor, selectionBackground, black, red, green, yellow, blue, purple, cyan, white, brightBlack, brightRed, brightGreen, brightYellow, brightBlue, brightPurple, brightCyan, brightWhite, taken from the palette (ansi[5] is `purple`, ansi[13] `brightPurple`), hex in lower case.

R18 Fragment profile. Unless --no-profile, `profiles` has one object with keys in this order: guid "{6b2d8b49-31d3-5dea-9087-93c26e1a033e}"; name "Serena"; commandline; startingDirectory "%USERPROFILE%"; colorScheme; font {"face": "Cascadia Code"}; environment {"SERENO_SESSION": "wt-profile", "POWERSHELL_TELEMETRY_OPTOUT": "1", "POWERSHELL_UPDATECHECK": "Off"}; autoMarkPrompts true; showMarksOnScrollbar true. The commandline value is (unescaped): %SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoLogo -NoExit -ExecutionPolicy RemoteSigned -File "%LOCALAPPDATA%\sereno\shell\init.ps1" for shell powershell, and the same with `pwsh.exe` as the program for shell pwsh; `auto` means pwsh when pwsh.exe is on PATH at apply time, otherwise powershell. If ROOT is not the default, the absolute path of init.ps1 replaces the %LOCALAPPDATA% form; a ROOT that cannot stand in a command line is then a refusal (exit 3): one that holds a double quote or a line break, or two or more percent signs (Windows Terminal expands %NAME% in a command line and has no way of writing a percent sign that stays one; a single sign cannot name a variable and is allowed). colorScheme is {"dark": "Serena Dark", "light": "Serena Light"} for mode auto with flavor soft, the Vivid pair for auto with vivid, and a single scheme name for a fixed mode (dark and light honour the flavor; hc and hc-light do not). With --no-profile, `profiles` is an empty array. The GUID is the documented UUIDv5 for application 'SerenaTerminal' and profile 'Serena'; a unit test of the function must also return {2ece5bfe-50ed-5f3a-ab87-5cd4baafed2b} for ('Git', 'Git Bash'). No other profile key is written (in particular not adjustIndistinguishableColors).

R19 What apply says about Windows Terminal. After writing a fragment with a profile it prints (key wt.notice.stub): 'Windows Terminal adds a short entry for the Serena profile to its own settings.json the first time it sees it, as it does for every fragment profile. sereno does not write that file. Use --no-profile to install only the colour schemes.' and (key wt.notice.open): 'Close every Windows Terminal window, open Windows Terminal again and choose Serena in the new-tab menu. One more window of a Windows Terminal that is already running is not expected to show what this apply changed.' Nothing in sereno claims that settings.json stays unchanged.

R20 Hook targets. `--hook` accepts powershell (Windows PowerShell 5.1, Windows only), pwsh, bash, zsh. Target file: powershell and pwsh use the value of $PROFILE.CurrentUserCurrentHost. An apply that names the shell in `--hook`, a dry run included, obtains it by running once `<exe> -NoProfile -NonInteractive -Command "$PROFILE.CurrentUserCurrentHost; Get-ExecutionPolicy"` (exe is powershell.exe or pwsh); this is the only child process sereno ever starts. It is started without the variable PSExecutionPolicyPreference, in which a PowerShell that was itself started with -ExecutionPolicy hands that policy down to its child processes: the policy asked for is the one a session of the user gets, not the one of the session sereno is run from. An apply that does not name the shell looks after a hook line of an earlier apply in the file the manifest records and, while that file is there, starts nothing; when the file is gone, it asks as an apply that names the shell does, so that a profile that has moved is refused, with `sereno uninstall --hook` named as the way out, and one that was deleted is created again only where PowerShell still names it and still loads profiles. If SERENO_PS_PROFILE_PATH (for powershell) or SERENO_PWSH_PROFILE_PATH (for pwsh) is set, that path is used and no process is started. bash uses $HOME/.bashrc (on Windows HOME, else USERPROFILE); zsh uses ${ZDOTDIR:-$HOME}/.zshrc. Refusals (exit 3): the shell's executable is not on PATH (powershell/pwsh only); on Windows the probe reports Restricted or AllSigned, in which case sereno prints, and does not run, `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`; the probe prints no profile path (PowerShell has none when the Documents folder is missing or out of reach) or does not answer within 15 seconds, after which it is stopped; these two refusals name the variable above as the way to tell sereno the path.

R21 Hook line text, one line, ASCII, ending with the marker `# sereno:hook`. With the default ROOT: Windows powershell and pwsh: if ($ExecutionContext.SessionState.LanguageMode -eq 'FullLanguage' -and [System.IO.File]::Exists("$env:LOCALAPPDATA\sereno\shell\init.ps1")) { . "$env:LOCALAPPDATA\sereno\shell\init.ps1" } # sereno:hook ; Windows bash and zsh (Git Bash): [ -r "$LOCALAPPDATA/sereno/shell/init.bash" ] && . "$LOCALAPPDATA/sereno/shell/init.bash" # sereno:hook (init.zsh for zsh); macOS and Linux bash and zsh: [ -r "$HOME/.local/share/sereno/shell/init.bash" ] && . "$HOME/.local/share/sereno/shell/init.bash" # sereno:hook ; pwsh on macOS and Linux: the PowerShell form with "$HOME/.local/share/sereno/shell/init.ps1". When ROOT is not the default (SERENO_HOME or XDG_DATA_HOME set), the absolute path is used in single quotes with quotes escaped for that shell. Because the line tests for the file first, it does nothing if sereno's files are gone. The PowerShell form asks for the language mode before it calls a method of .NET: in a session that an application control policy has put into ConstrainedLanguage mode it does nothing and prints nothing (R23). It names no cmdlet, so it loads no module.

R22 Hook editing rules. The target must be absent or a regular file; a symlink, a directory, an unreadable file, a read-only file, a file over 1 MiB or one the line would take over 1 MiB, a UTF-16BE file, or a file with NUL bytes and no UTF-16LE BOM is a refusal that prints the line so the user can add it by hand. A UTF-16LE file (BOM FF FE) gets the line encoded as UTF-16LE; any other file gets ASCII bytes, with an existing BOM left alone. Line ending: CRLF if the file contains any CRLF, otherwise LF; a new file uses CRLF for powershell and pwsh on Windows and LF otherwise. The line is appended at the end: if the file is non-empty and does not end with a line ending, one is added first; then the line; then one line ending. The exact inserted bytes are stored in the manifest. A line is sereno's when it ends with a space and the marker, spaces and tabs after the marker aside; a line that only mentions the marker elsewhere (in a string, in the middle of a comment) is the user's and is never touched. If a line of sereno's already exists and is identical, nothing changes; if it differs, that line is replaced in place and the plan shows the line that goes. An absent file is created together with missing parent directories, all recorded. Before the first edit of an existing file its bytes are copied to ROOT/backups, with permission bits no wider than those of the file, and its SHA-256 recorded. On Windows, when `--hook bash` would create ~/.bashrc and none of ~/.bash_profile, ~/.bash_login, ~/.profile exists, the plan adds the note that Git for Windows will create ~/.bash_profile by itself.

R23 Rules for all three init files. They are rendered by apply from embedded templates and the palette, are identical for every user of the same version (no path, user name or machine fact inside), contain only ASCII bytes, print nothing, start no process, and are safe to source twice (a guard variable makes the second run a no-op). They find ROOT from their own location ($PSScriptRoot, ${BASH_SOURCE[0]}, zsh %x). init.ps1 must parse without errors on Windows PowerShell 5.1 and PowerShell 7 and uses [char]27, never the backtick-e escape; it returns immediately unless $Host.Name is 'ConsoleHost', and unless the language mode of the session is FullLanguage (where an application control policy puts PowerShell into ConstrainedLanguage mode, methods of .NET types cannot be called; such a session is left as it is: no colours, no prompt, no message). 'Print nothing' holds for a variable of the user's that is read-only as well: PS1 or PROMPT, PROMPT_COMMAND or precmd_functions, LS_COLORS and LSCOLORS are then left as they are, without the error an assignment would print. init.bash must pass `bash -n` under Bash 3.2.57 and 5.x and returns unless the shell is interactive; init.zsh must pass `zsh -n`.

R24 init.ps1, line-editor colours. When the command Set-PSReadLineOption is available, set -Colors with: Command ESC[34m; Keyword ESC[35m; String ESC[32m; Number ESC[93m; Type ESC[33m; Member ESC[36m; Variable ESC[39m; Parameter ESC[3;37m; Operator ESC[37m; Comment ESC[90m; Error ESC[91m; Emphasis ESC[96m; Selection ESC[7m; Default ESC[39m; ContinuationPrompt ESC[90m. Additionally, only when the property exists on Get-PSReadLineOption: InlinePrediction ESC[90m; ListPrediction ESC[33m; ListPredictionSelected ESC[7m. Verified today on PSReadLine 2.0.0: the fifteen base keys including ESC[3;37m and ESC[7m are accepted and InlinePrediction is rejected, hence the property check. This applies in profile sessions and in hook sessions, and not in a plain console (R26): there the colours PSReadLine has are left as they are.

R25 init.ps1, pairs measured as failing. (a) On PowerShell 5 and older (no $PSStyle), set $Host.PrivateData.ProgressForegroundColor and ProgressBackgroundColor to $Host.UI.RawUI.ForegroundColor and BackgroundColor inside try/catch (the stock Yellow on DarkCyan is 1.14-1.46:1 on the six variants); a session that has no console, where the host names no colours, keeps the ones it has, and nothing is assigned. (b) Where $PSStyle exists, for $PSStyle.Progress.Style, every $PSStyle.Formatting value, $PSStyle.FileInfo.Directory, SymbolicLink, Executable and every FileInfo.Extension entry: if the value contains an SGR parameter 40-47 or 100-107, replace that parameter with the same number minus 10; members that do not exist are skipped. The known case is FileInfo.Directory = ESC[44;1m in PowerShell 7.6.6, which becomes ESC[34;1m (the stock value is 1.45-2.23:1 on the six variants). Not in a plain console (R26): there none of these values is changed. After init, a test asserts that none of those values contains a background parameter, and in a plain console that each is what it was.

R26 init.ps1, prompt. The Serena prompt is installed only when the mode file says prompt=on and the current prompt is the stock one: its definition, after removing lines that start with # and trimming, equals "PS $($executionContext.SessionState.Path.CurrentLocation)$('>' * ($nestedPromptLevel + 1)) "; (read on 5.1 today; asserted for pwsh in CI). The prompt returns, in order: [marks]; ESC[34m PATH ESC[0m; if on a branch, a space and ESC[35m BRANCH ESC[0m; if the last command took 2 seconds or more, a space and ESC[90m N.Ns ESC[0m (invariant culture, one decimal); a line feed; ESC[32m if $? was true at entry, otherwise ESC[31m; the character > repeated $nestedPromptLevel + 1 times; ESC[0m; one space; [end mark]. PATH is the current location with a leading $HOME replaced by ~. BRANCH is read without git: walk up from the file-system path to a `.git` directory, or a `.git` file whose `gitdir: ` line points to one, read HEAD; `ref: refs/heads/X` gives X, anything else gives its first 7 characters; only on the FileSystem provider; a file that cannot be read at that moment gives a prompt without the branch. Marks, only when WT_SESSION is set and TERM_PROGRAM is not vscode: from the second prompt on ESC]133;D;CODE BEL (CODE is 0 if $? was true, else $LASTEXITCODE if non-zero, else 1), then ESC]133;A BEL, then ESC]9;9;"PROVIDERPATH" BEL on the FileSystem provider; the end mark is ESC]133;B BEL. $LASTEXITCODE is preserved. If the prompt is not stock, it is left alone and only wrapped as described in R30. A plain console is a console window of Windows itself whose background is not black: the session runs on Windows, WT_SESSION is not set, TERM_PROGRAM is not vscode, and $Host.UI.RawUI.BackgroundColor names a colour other than Black. There the background is an entry of the console's own colour table, and a slot colour would be one entry of that table on another (the window of Windows PowerShell has entry 5 as its background, which is the slot of the keyword and of the branch). In a plain console the prompt returns the same text without any sequence: PATH; if on a branch, a space and BRANCH; if the last command took 2 seconds or more, a space and N.Ns; a line feed; the character > repeated $nestedPromptLevel + 1 times; one space.

R27 init.ps1, comfort set. Applied only when the mode file says keys=always, or keys=profile and the session is a Serena profile session (R30), and Set-PSReadLineKeyHandler is available: Set-PSReadLineOption -BellStyle None -HistoryNoDuplicates -HistorySearchCursorMovesToEnd; Tab bound to MenuComplete; UpArrow to HistorySearchBackward; DownArrow to HistorySearchForward; and, only if the PredictionSource parameter exists, its current value is None and PSReadLine can show predictions in that session, PredictionSource History (on Windows PSReadLine refuses predictions where the output is redirected or the console has no virtual terminal sequences; there the option is not asked for). Nothing else is rebound; no module other than PSReadLine is imported; no alias or completion is defined in 0.1.

R28 Mode resolution (one table, testdata/modes.tsv, with columns mode, flavor, hc_on, hc_light, apps_light, variant; implemented in Go, in init.ps1 and in init.bash/init.zsh, and all three are tested against the same file). mode=auto: if hc_on then hc-light when hc_light else hc; otherwise light when apps_light else dark, with flavor vivid giving light-vivid or dark-vivid. mode=dark or light: that variant, honouring flavor. mode=hc or hc-light: that variant. Windows signals, read in-process under HKEY_CURRENT_USER: hc_on is bit 0 of the integer in Control Panel\Accessibility\HighContrast value Flags; hc_light is true when 0.2126 R + 0.7152 G + 0.0722 B of Control Panel\Colors value Window (three decimal numbers) is above 127; apps_light is Software\Microsoft\Windows\CurrentVersion\Themes\Personalize value AppsUseLightTheme equal to 1. A value that cannot be read counts as off or dark. PowerShell reads them with [Microsoft.Win32.Registry]::GetValue; Git Bash reads the files under ${SERENO_REG_ROOT:-/proc/registry/HKEY_CURRENT_USER} with the read builtin (the DWORD is 4 raw bytes: light when the first byte is non-zero). The environment variable SERENO_OS_MODE (dark, light, hc, hc-light) replaces the signals. On macOS and Linux there is no detection in 0.1: the signals are unknown and auto resolves to dark for painting purposes.

R29 Palette byte strings. For a variant, PALETTE is twenty sequences and nothing else, each ending in ST: ESC]10;rgb:RR/GG/BB (foreground), ESC]11;... (background), ESC]12;... (cursor), ESC]17;... (selectionBackground), then ESC]4;N;rgb:RR/GG/BB for N = 0 to 15, hex in lower case. RESET is ESC]104 ST, ESC]110 ST, ESC]111 ST, ESC]112 ST, ESC]117 ST. Both are produced by one Go function and embedded as constants in the init files; a golden file per variant fixes the bytes.

R30 Following the system (PowerShell and Git Bash on Windows). A session is a Serena profile session when SERENO_SESSION equals wt-profile or WT_PROFILE_ID equals the GUID of R18 ignoring case. The follow check is active only when all hold: WT_SESSION is set; TERM_PROGRAM is not vscode; the mode file's inband is not off; and inband is always or the session is a Serena profile session. When active, at every prompt the hook re-reads the mode file if it changed (PowerShell compares LastWriteTimeUtc; bash and zsh read the five lines with builtins; a changed file that cannot be read at one prompt, because another program holds it at that moment, is read at the next), resolves the variant by R28 and, only if it differs from the last variant emitted in this session (the first prompt always differs), writes PALETTE to the console ([Console]::Out.Write in PowerShell, printf in bash and zsh). With the Serena prompt the check runs at the start of the prompt function. With a foreign prompt in PowerShell, init.ps1 saves it and defines a wrapper that calls the saved prompt first, then runs the check, then returns the saved prompt's output unchanged. There is no background process and no switching while the shell sits idle: the change shows at the next prompt.

R31 init.bash. Guard and interactivity check as in R23. Prompt, only when prompt=on and none of STARSHIP_SHELL, POSH_PID, POSH_THEME is set: a function is put first in PROMPT_COMMAND, keeping any existing value (string or array); it records $?, finds the branch as in R26 using only builtins, stores it in the variable __sereno_branch, and sets PS1 to \[ESC[34m\]\w\[ESC[0m\], then (when on a branch) a space and \[ESC[35m\]${__sereno_branch}\[ESC[0m\], then \n, \[ESC[32m\] or \[ESC[31m\] by status, >, \[ESC[0m\] and a space. The branch name is never pasted into PS1 as text; PS1 only references the variable, so a hostile branch name cannot run a command. The follow check of R30 is compiled in but active only where the registry tree of R28 is readable. A PROMPT_COMMAND that is read-only (an audit setting on shared machines) cannot take the function: the session then keeps its prompt, does not follow the system and gets the ls colours only. A PS1 that is read-only keeps the prompt it has; the session still follows the system. No key binding, alias, completion or history setting is touched.

R32 init.zsh. Same scope as R31. The function is appended to precmd_functions; it sets psvar[1] to the branch (empty when none) and PROMPT to %F{4}%~%f%(1V. %F{5}%1v%f.), a newline, %(?.%F{2}.%F{1})>%f and a space. Not installed when prompt=off or any of STARSHIP_SHELL, POSH_PID, POSH_THEME, ZSH (oh-my-zsh) or P9K_VERSION is set. A read-only precmd_functions, PROMPT or psvar is treated as R31 treats PROMPT_COMMAND and PS1. zsh is tier 2: tested in CI only.

R33 ls colours in bash and zsh. If LS_COLORS is unset or empty (GNU ls takes an empty value like a missing one and uses its built-in table), set it to di=1;34:ln=36:so=35:pi=33:ex=1;32:bd=1;33:cd=1;33:su=1;31:sg=1;33:tw=4;34:ow=4;34:st=4;34:or=31:mi=31. If it has a value, rewrite only entries whose value contains a parameter 40-47 or 100-107: su, sg, tw, ow, st, ca, bd, cd, pi, or, mi, do take the value above (ca=31, do=1;35); any other such entry just loses those parameters. If LSCOLORS is unset or empty, set it to exfxcxdxbxDxDxBxDxExEx (no backgrounds). CLICOLOR, aliases for ls, and GREP_COLORS are not touched. Reason: GNU ls's built-in ow=34;42 is 1.01-1.44:1 on the six variants.

R34 Reaching the binary from a session. If ROOT/bin/sereno (sereno.exe on Windows) exists and no program named sereno is on PATH, each init file defines a function `sereno` that calls it with the same arguments. Nothing is added to PATH.

R35 `sereno theme` settings. Requires a previous apply (otherwise exit 3 with the hint to run `sereno apply`). A positional mode, --flavor or --inband updates the mode file and the manifest hash; if a fragment with a profile is installed, its colorScheme is re-rendered by R18. Whether it has a profile is read from the fragment file, not from the recorded option. The fragment is rendered from the mode file as it stands afterwards: when the mode file is left as it is under R15, the setting that was asked for is not stored, and the fragment gets what the file says. With no argument it prints the setting, the signals, the resolved variant and the palette route (R37). After any of these, if stdout is a terminal and painting is allowed (R36), it writes PALETTE for the resolved variant, so `sereno theme` alone also repaints a tab whose palette was reset by Windows Terminal. On macOS and Linux `sereno theme auto` stores the setting and prints that automatic detection is not part of 0.1 and that the emulator's own light/dark pair is the supported route (see `sereno export`).

R36 `sereno theme --paint VARIANT`, `--reset`, `--show`. --paint writes PALETTE for that variant to stdout and touches no file; it works without any apply (a zero-footprint trial in any emulator that honours OSC 4, 10, 11, 12). --reset writes RESET. Painting is refused with exit 3 when stdout is not a terminal, when TERM_PROGRAM is vscode, or when TMUX is set or TERM starts with screen or tmux. --show prints the 16 slots as swatches, one sample line per role of R8 and the contrast minimums of R9 for the resolved variant.

R37 `sereno status`. Starts no process and writes nothing. Text output mirrors the JSON, whose keys are: version; os; root; applied; lang; mode {mode, flavor, inband, keys, prompt}; signals {appsLight, highContrast, hcLight} or null; variant; session {emulator: windows-terminal|vscode|other, serenaProfile, paletteRoute: in-band|host|emulator}; windowsTerminal {detected, fragment, profile (the installed fragment file has a profile), settingsPath, theme, defaultsOverride (list of keys among colorScheme, font, environment set in profiles.defaults), stubPresent, guidKnown}; hooks [{shell, path, present}]; owned {total, modified, missing}; pwsh {onPath}; warnings [{id, text}]. Warning ids: wt.not-detected; wt.theme-not-system (the scheme pair alone will not follow Windows; in-band does); wt.defaults-override; wt.profile-suppressed (the GUID is in state.json generatedProfiles, the fragment has a profile, and settings.json has no entry with that GUID: Windows Terminal will keep the profile hidden; the text shows the exact object to add to profiles.list: guid, hidden false, name Serena, source SerenaTerminal); wt.settings-unreadable; owned.modified; owned.missing; hook.missing; session.vscode; pwsh.absent (text includes the exact command `winget install -e --id Microsoft.PowerShell --source winget`, which sereno never runs); unix.auto-unsupported. settings.json and state.json are read only, with comments tolerated; a parse failure is a warning, never an error. Exit 0 unless status itself fails.

R38 `sereno export`. Writes six files per target: ghostty/<Scheme Name> (no extension) with lines `palette = N=#rrggbb` for N 0-15, then background, foreground, cursor-color, selection-background, selection-foreground as `key = #rrggbb`; kitty/<Scheme Name>.conf with `foreground`, `background`, `cursor`, `selection_foreground`, `selection_background`, `color0` to `color15`, each as `key #rrggbb`; wezterm/<Scheme Name>.toml with a [colors] table (foreground, background, cursor_bg, cursor_border, cursor_fg = background, selection_bg, selection_fg, ansi = 8 strings, brights = 8 strings) and [metadata] name; alacritty/<id with serena- prefix>.toml with [colors.primary] background, foreground; [colors.cursor] cursor, text = background; [colors.selection] background, text; [colors.normal] and [colors.bright] black, red, green, yellow, blue, magenta, cyan, white. Default destination ROOT/themes (requires a previous apply; files are added to the manifest). With --to DIR the files are written there, are not tracked, and an existing different file is a refusal; ROOT and its manifest are then neither read nor written. After writing it prints, per target, where to copy the files and the activation line (Ghostty: `theme = dark:Serena Dark,light:Serena Light`; kitty: copy as dark-theme.auto.conf and light-theme.auto.conf for automatic switching; WezTerm: config.color_scheme; Alacritty: an import entry). It never writes into an emulator's own folders. The format keys come from the emulators research of today and were not re-read by me; the README labels these four as generated and not visually verified.

R39 `sereno uninstall` (this is the undo). In order: (1) for each recorded hook: if the recorded inserted bytes stand in the file as whole lines, remove exactly them; otherwise (the user commented the line out, indented it, or changed the file's line endings) remove every line ending with `# sereno:hook`, as a whole line, and nothing else; a profile that has become read-only or something sereno does not edit is left alone and reported with the line, which ends the run with exit 4; if sereno created the file and it is now empty, delete it and then the directories sereno created for it if empty; if the result's SHA-256 equals the recorded beforeSha256 (or the file is gone and did not exist before), delete the backup, otherwise keep the backup and print its path (the user changed the file since; that is not an error); a recorded file that is not there is not looked for anywhere else, and after the plan one sentence names the shell and the recorded file and says that the line may still be in the file if it was moved, where it is the user's to delete (the exit code is not affected); (2) for each owned path: missing is fine; hash equal to the recorded one: delete; different: leave it, report it, final exit 4; (3) delete mode and manifest.json, then backups/ if empty, then every directory in dirs in reverse order if empty, then ROOT if empty. `--hook LIST` performs only step (1) for the named shells and updates the manifest. `--dry-run` prints the plan only. What it restores: every file sereno created is gone, every profile it touched is byte-identical to its state before the hook (when the user has neither edited nor moved it since; a profile that has moved keeps the line and is not deleted, also where sereno had created it, and the folders sereno had made for it stay too where they moved along with it), and directories it created are gone. What is left in place by a complete uninstall is no longer recorded anywhere, and the text says so: it is the user's to remove, and running the command again finds nothing. What it does not restore, and says so whenever one of the two files holds it or cannot be read, also after an apply with --no-profile: the entry Windows Terminal itself added to settings.json and the GUID in its state.json (advice printed: leave the entry; once Windows Terminal has been closed and opened again it is expected to leave Serena out of its new-tab menu and to go on listing it in its settings, as a profile that is no longer detected, with a button to delete it; deleting the entry makes a later reinstall stay hidden until the entry is added back), and the sereno program file (it prints its path).

R40 What gets installed. sereno 0.1 installs no tool, font, shell, emulator or package manager, and has no flag to do so. The only software placed on the machine is the sereno binary itself, by `go install github.com/joaooliveira10/serena-terminal/cmd/sereno@v0.1.0` (Go 1.24 or newer), by a release archive, or by the install script of R41. Informational only: `status` shows the winget command for PowerShell 7 (today 7.6.6.0, installer type msix in the winget manifest, silent mode supported; whether it needs elevation was not tested).

R41 Release. A tag v* runs .github/workflows/release.yml on ubuntu-latest: `go build -trimpath -ldflags "-s -w -X main.version=<tag>"` for the six targets; archives sereno_<version>_<os>_<arch>.zip (windows) or .tar.gz (others) containing the binary, LICENSE and README.md; checksums.txt with SHA-256 of each archive; install.ps1 and install.sh rendered from templates with the tag and those checksums; an attestation by actions/attest-build-provenance; `gh release create --draft` with all assets. Every action is pinned by commit SHA; permissions are contents: write, id-token: write, attestations: write for this workflow and contents: read for CI; no secret other than GITHUB_TOKEN. install.ps1 (runs on Windows PowerShell 5.1) and install.sh (POSIX sh) download the archive for the machine's architecture from that tag, compare SHA-256 with the embedded value, stop on mismatch, place only the binary in ROOT/bin, change nothing else (no PATH edit), print the next command (`sereno apply --dry-run` by full path) and support -Uninstall / --uninstall to remove ROOT/bin.

R42 Performance budgets. On the owner's machine, under Windows PowerShell 5.1: dot-sourcing init.ps1 takes at most 80 ms in a Serena profile session and at most 65 ms in a hook session (prototypes measured 28 and 53 ms; the finished file 68 to 72 ms and 55 to 60 ms, and 71 to 73 ms and 59 to 63 ms as it is after the first runs in CI). What is judged is the time around the dot-sourcing, taken inside the process: the median of 9 fresh `powershell.exe -NoProfile` processes that loaded PSReadLine first and have no start-up profile of an earlier process to replay. PowerShell keeps such a profile below the home folder and compiles ahead of their use the methods the process before it compiled, so a session that follows one of its kind is faster (62 and 55 ms); the first of its kind is what the budget is on, because it is the slowest and does not depend on what ran before. The difference between the medians of whole processes with and without the file is printed and not judged: a PowerShell start takes 300 to 400 ms and varies by more than init.ps1 costs. One prompt with the follow check active costs at most 2 ms (mean of 200 calls; prototypes 0.33-0.46 ms; the finished prompt 0.8 ms). The first prompt of a session costs more, once, because its code runs for the first time; it is printed and not judged: 57 to 63 ms in a Serena profile session and 32 to 34 ms in a hook session, inside a repository. Before its first prompt a new Serena tab therefore waits about 130 ms for sereno, and a hooked session about 90 ms, on top of the start of PowerShell itself. The hook line of R21 is not in these figures, and bench.ps1 does not time it. A hook line is read by every powershell.exe that is not started with -NoProfile, also by one that runs a command and ends. CI gates are looser: 150 ms and 10 ms for PowerShell 5.1 and 7 on Windows and for pwsh elsewhere, except that PowerShell 7 on Windows has 210 ms; 60 ms and 10 ms for bash and zsh, where the sourcing is timed inside the shell in the same way. Init and prompt must also succeed with PATH emptied, which proves no child process.

R43 Explicitly not done in 0.1: no emulator is built, bundled, installed or configured beyond the Windows Terminal fragment; no edit of settings.json (default profile, application theme, key bindings); no PowerShell 7 or PSReadLine installation or upgrade; no Starship, fzf, zoxide, bat, eza, fd, ripgrep, tealdeer, delta, Atuin, Carapace, mise; no fonts or icons; no completions, aliases, abbreviations, history tools; no keys, explain, doctor or AI; no OS detection on macOS or Linux; no in-band painting by default outside Windows Terminal; no tmux, screen, Zellij, WSL or SSH handling; no fish, Nushell or cmd; no iTerm2, Ptyxis, Rio, foot, Konsole or Terminal.app files; no winget, Scoop, Homebrew or distro packages; no code signing; no self-update or update check; no custom palettes; no switching while the shell is idle; Windows without Windows Terminal (conhost) gets the hook's colours only, and none of them in a plain console (R26); Windows Terminal older than 1.24 is not verified.

## Test plan

T1 Hermetic rule for every automated test (local and CI): each test creates a temporary directory, points LOCALAPPDATA, USERPROFILE, HOME, XDG_DATA_HOME and the two SERENO_*_PROFILE_PATH variables into it, and sets SERENO_SANDBOX to it, so a write outside it fails the test (R10). ## Biggest risks

- The in-band route is verified in Windows Terminal's source (release-1.24: OSC 4/10/11/12/17 parsed, background change propagated to the control) but was not seen on screen when this was written (it was on 2026-10-08, for the light palette: see the section "What the owner saw on a screen"). Mitigation: spike T11 before any feature work; the fallback (inband off, scheme pair only) is already part of the design, so 0.1 ships either way.
- Windows Terminal writes on its own. The first time it loads the Serena profile it adds a stub to settings.json, records the GUID in state.json and re-serialises settings.json from its model (comments and formatting in that file are not expected to survive; inferred from the code, not tested). After uninstall the stub remains; if the user deletes it and reinstalls, the profile stays hidden. Mitigation: said before apply and after uninstall, `--no-profile` avoids it entirely, `status` detects the hidden case and prints the fix. Byte-identical uninstall is claimed for sereno's writes only.
- First frame for light-mode users: with Windows Terminal's default theme (dark) a new Serena tab opens on Serena Dark and repaints at the first prompt, roughly 150-300 ms later; a settings reload in Windows Terminal resets an open tab to the profile's scheme until the mode changes or `sereno theme` is run. Mitigation: `status` and the README say that setting Windows Terminal's theme to 'Use Windows theme' removes both; the backed-up edit is offered in 0.3.
- A bug in the hook editor could damage a profile, which would cost the project its credibility. Mitigation: hooks are opt-in; symlinks and unknown encodings are refused; a backup is taken before any edit; removal is by exact bytes; fixtures for CRLF, BOM and UTF-16; whole-tree hash tests on three systems; SERENO_SANDBOX in every test.
- PowerShell edge cases: OSC bytes in the prompt and PSReadLine's width accounting; differences between PSReadLine 2.0.0 and 2.4.x; a user's profile.defaults overriding the fragment's scheme, font or environment (the fragment is the least important layer); Group Policy execution policies; Documents redirected to OneDrive. Mitigation: palette bytes are written to the console, not returned in the prompt; marks follow Microsoft's documented pattern; feature detection by property; WT_PROFILE_ID as a second way to recognise the Serena session; `status` warnings; tests on 5.1 and 7.6.
- High-contrast polarity from the Window colour is an assumption, and PowerShell 7 behaviour could not be tried locally (pwsh is not installed; defaults were read from the v7.6.6 source). Mitigation: T11 S4 and CI on pwsh 7.6; SERENO_OS_MODE overrides detection.
- 0.1 is thin on macOS and Linux (shell layer, exported themes, manual paint; no detection) and zsh and macOS can only be tested in CI. It may be read as a Windows project. Mitigation: a support matrix with explicit tiers in the README; 0.2 is scoped to exactly that gap; tier-2 files are labelled as not visually verified.
- Unsigned Go binaries may meet SmartScreen, antivirus heuristics or macOS quarantine; behaviour for downloads through PowerShell or curl was not tested. Mitigation: `go install` builds locally; install scripts verify SHA-256; attestations are published; signing through SignPath Foundation is applied for once releases exist.
- Sixteen slots cannot carry the whole Serena role palette: constant and parameter have no slot of their own, programs that print fixed foreground-on-background pairs stay hard to read (0 of 120 such pairs pass on the light variants), and slot 0 as text is unreadable on the dark variants (1.21-1.52:1). Mitigation: sereno never writes such pairs, fixes the four it measured (PSReadLine selection, PowerShell 5.1 progress, PowerShell 7 directories, ls), publishes the matrix in docs/contrast.md; any palette change is made in Serena Theme first and imported.
- Name confusion with oraios/serena and the word 'Terminal' suggesting an emulator. Mitigation: the command is `sereno`; the first README sentence says what the project is not.
- Scope growth and adapter rot for one maintainer (the research cites Omarchy's 4,998 open items). Mitigation: tier 1 is one emulator and one shell family; everything else is generated or deferred; a rule in the ADRs that nothing enters before 0.4 unless it serves the differentiator.
- Upstream drift: Windows Terminal could change fragment or OSC behaviour, ubuntu-latest changes image in November 2026, PowerShell 7 moves to MSIX only. Mitigation: the fragment uses only keys present in the release-1.24 schema (checked in CI against a stored copy), tests avoid image-specific assumptions, pwsh.exe is resolved through PATH.

## Where the research disagreed

- Go binary from day one (distribution and build-options research, two proposals) versus scripts only in 0.1 (smallest-useful). Resolved for Go: the brief asks for growth without a rewrite, the script proposal itself schedules the Go engine for 0.4, and package syscall covers the registry so there are zero dependencies. From the script proposal I kept the create-only default and the static payload.
- WezTerm as the reference emulator (emulators research, best-experience) versus no emulator (the other two). Resolved for none: the GitHub API today still returns 20240203-110809-5046fc22 as the latest release, current code exists only as nightlies, the Windows installer elevates, and requiring an emulator contradicts working with what the user already has. Windows Terminal is the tier-1 host; WezTerm gets a generated scheme now and a private config after its next stable.
- PowerShell 7 as the only supported shell, on every OS (shells research) versus Windows PowerShell 5.1 as a first-class target (smallest-useful, most-distinct). Resolved for supporting both by feature detection and never installing 7: the machine has only 5.1, the winget package is a 335 MB msixbundle, and what 5.1 lacks has nothing to do with colour. Verified today on PSReadLine 2.0.0: all fifteen colour keys accept SGR strings including italic and reverse video. On macOS and Linux the native shells (bash, zsh) get a small layer; pwsh there is not required.
- Eight-tool core with Starship (tools research, best-experience) versus no tools (the other two). Resolved for none in 0.1: a from-zero user must see the result before installing anything, Starship spawns a process per prompt on Windows (its issues 7677 and 6875 are still open), and package installation is the least testable part. The tools return as optional adapters in 0.3.
- 'settings.json stays byte-identical' (best-experience and most-distinct acceptance tests) versus 'Windows Terminal rewrites it' (smallest-useful). The latter is correct: DisableDeletedProfiles returns true for a newly seen fragment profile and WriteSettingsToDisk follows (release-1.24 source), and the owner's settings.json already contains such stubs for Git and Microsoft.WSL. Acceptance now compares only sereno's own write set.
- Smallest-useful advises deleting the stub by hand after uninstall. Corrected: the GUID stays in state.json generatedProfiles, so a profile that reappears without its stub is marked deleted and hidden. Advice is to leave the stub; `status` detects the hidden case.
- Documentation says Windows Terminal's theme defaults to 'system' (a page from 2022, quoted in the research); the shipped defaults.json says "dark" on release-1.24, release-1.25 and main. The source wins, which is exactly why the in-band route is needed.
- Selection legibility: smallest-useful reports bright black on the selection colour at 2.60:1 as a risk. In Windows Terminal 1.24 selected text is drawn in black or white according to the lightness of the selection colour, so the risk does not exist there. For emulators that keep the text colour, the exported files set an explicit selection foreground, and the contrast gate checks both rules.
- golang.org/x/sys as a dependency (most-distinct) versus zero dependencies (best-experience). Resolved for zero: syscall.RegOpenKeyEx and RegQueryValueEx exist in the standard library.
- Role-to-slot tables differ between the three proposals (type on 3 or 11, number on 3 or 11, parameter on 9 or italic 7, error on 1 or 9). Resolved by the palette itself: type is exactly ansiYellow, so type 3 and number 11; parameter is italic slot 7 because bright red would read as an error; error is 9. The two roles without a slot are a visual judgement confirmed in spike T11.
- Fragment content: a static light/dark pair (smallest-useful) versus a starting scheme chosen from the OS mode at apply time (most-distinct). Resolved for the pair in auto mode and a single scheme only for a fixed mode: the payload stays deterministic and the pair is right whenever the user sets Windows Terminal's theme to system. Cost: the first-frame flash listed under risks.
- One profile that picks the best PowerShell (best-experience) versus two profiles (smallest-useful). Resolved for one profile named Serena with `--shell auto|powershell|pwsh`, so the GUID and the menu entry stay stable.
- adjustIndistinguishableColors in the Serena profile (most-distinct) versus not setting it. Resolved for not setting it in 0.1: its effect on Serena's own slots is unverified.
- OS detection on macOS and Linux in 0.1 (most-distinct, at shell start) versus none. Resolved for none: it cannot be checked without a Mac, and the emulator's own light/dark pair fed by `sereno export` is the supported route there until 0.2.
- Entry on macOS and Linux: ZDOTDIR and --rcfile wrappers through `sereno shell` (best-experience) versus a one-line hook (most-distinct). Resolved for the opt-in hook only; the wrappers change where zsh reads its other files and history, which nobody verified.
- A separate `undo` command (best-experience, distribution research) versus only uninstall. Resolved: with a write set of owned files plus at most four hook lines, `uninstall` and `uninstall --hook LIST` are the undo; a transactional undo arrives with the first edit of a file sereno does not own (0.3).
- State layout on macOS and Linux: four XDG folders (best-experience), three (most-distinct) or one (smallest-useful). Resolved for one root, ${XDG_DATA_HOME:-$HOME/.local/share}/sereno, so removal is one folder.
- CI runners: the proposals pin windows-2025, macos-15 and ubuntu-24.04; the brief asks for windows-latest, macos-latest and ubuntu-latest. Resolved for the latest labels as asked; today they are Windows Server 2025, macOS 26 arm64 (not macOS 15) and Ubuntu 24.04, and the tests are written against the shells, not the images.
- Packaging on day one: GoReleaser with Scoop and Homebrew (distribution research, most-distinct) versus a zip (smallest-useful). Resolved in between: plain `go build` in the release workflow, archives, checksums, attestation, install scripts and `go install`; Scoop and Homebrew in 0.2, winget in 0.3. Fewer third-party actions, and a draft release so publication stays with the owner.
- Fonts: Cascadia Code plus Symbols Nerd Font as default (tools research) versus nothing installed (all three proposals). Resolved for nothing installed: Cascadia Code is bundled with Windows Terminal (four TTF files seen in the package folder today) and the prompt is ASCII.
- Facts I did not re-verify today and therefore did not build 0.1 on: the PowerShell behaviour of Atuin and Carapace (the tools research cites their docs; both are deferred), the exact theme-file keys of Ghostty, kitty, WezTerm and Alacritty (taken from the emulators research; the export is labelled tier 2), whether the PowerShell msix needs elevation under winget (the manifest lists msix with silent mode and no elevation requirement; not tested, and sereno never installs it), and whether a new fragment is picked up without restarting Windows Terminal (recorded in T12).

## Amendments after the review of stage 1

Made on 2026-10-07, each following a finding of the independent review of the foundation packages. The requirement texts above already carry them.

- R13: when phase 2 stops before its end, the manifest is corrected so that it records only what was carried out. Before, the files a failed run never wrote counted as edited by the user from then on. Not covered: a process that is killed between the manifest and a file it was about to replace. That file then counts as edited until it is deleted by hand; closing this gap needs a record of the previous hash, that is, a change to the manifest format of R12, which was not made.

## Amendments after the review of stage 2

Made on 2026-10-08, each following a finding of the independent review of the renderer and the templates. The requirement texts above already carry them. The first one changes a figure the owner set and is his to confirm.

- R42, for the owner to confirm: the budget of init.ps1 was 60 ms, judged on the difference between the medians of whole processes with and without the file. The review showed that this difference cannot decide such a limit (76, 77 and 18 ms in three runs on the same file) and that the file does not meet 60 ms in a Serena profile session. Now the time around the dot-sourcing is judged, inside the process, in a process that has no start-up profile of PowerShell to replay; the figures are 80 ms for a Serena profile session and 65 ms for a hook session; the cost of the first prompt is stated. The reviewer proposed 80 and 60. The hook figure is 65 because the two guards this stage added (the language mode, the bytes of the mode file) cost about 2 ms, which puts the measured 55 to 60 ms too close to 60 for a gate that is not to fail by chance. The other way of answering the finding is to do less at the start; in a first session of its kind the comfort set of R27 costs about 12 ms, the line-editor colours of R24 about 10 ms and the progress colours of R25 about 6 ms, and about 15 ms go to PowerShell for reading a file of this size before its first line runs.
- R11 and R28: the bytes of the mode file decide in all three implementations. init.ps1 read the file as text and so accepted one with a byte order mark, which Go and bash reject.
- R18: a moved ROOT with two or more percent signs is refused, as one with a double quote already was. Windows Terminal expands %NAME% in the command line, and whether a name between two signs is a variable is only known on the machine, when the profile starts.
- R23: init.ps1 leaves a session in ConstrainedLanguage mode alone; before, it failed at its second line and replaced the prompt by one that failed too. Only the language mode of a test process was set to try this; it was not confirmed on a machine with an application control policy. Also R23, R31 and R32: a read-only PS1, PROMPT, PROMPT_COMMAND, precmd_functions, LS_COLORS or LSCOLORS is left alone without a message. The zsh half of this was written from the manual and has not run.
